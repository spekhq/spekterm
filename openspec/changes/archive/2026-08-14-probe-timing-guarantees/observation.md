# 處置的鑑別力觀測（tasks 8.4）

**為什麼要有這份紀錄**：本 change 的核心處置（停用背景節流）針對的是一個**偶發**現象，而
前置調查一度以「同一段落、唯一差別是兩個旗標」的**單輪對照**宣稱它有效 —— 那是站不住的：
自己的資料裡就有反例（同一段落、同樣未處置，`openspec-basics-1` 紅而 `openspec-basics-2` 全綠）。
**一個以單輪對照建立的處置，等於沒有對照組。**

## 方法

每輪同時做兩件事：跑 `PROBE_ONLY=runPanelBasics:dev npm run probe:openspec`，並自外部連上
port 9229 **持續**取樣 renderer 的可見性與 rAF。

**觀測者立即連線，不固定 sleep** —— 前置調查的旗標側之所以完全沒有資料
（`watch-openspec-flag.log` 是 0 bytes），正是因為它固定等了 25 秒，而那一輪 12.5 秒就跑完了。

## 判讀

- **主要判準取「≥2s 的往返區間數」**：它是這個病的直接指紋（未處置 3–4 個，處置後 **8 輪全部
  為 0**），而總耗時會被段落長度稀釋、紅燈數會被那個現象的偶發性稀釋。
- **`openspec-basics-2` 那一輪是最重要的一列**：它 37/37 全綠，卻是 hidden 且 CDP 阻塞 16.6 秒。
  **「這一輪沒有紅燈」不等於「這一輪沒撞到」** —— 這正是為什麼判準不能只看紅燈。
- **統計上的強度**：若處置無效、且每輪撞到的機率與前置調查相同（觀測到的下界 ≈ 3/7），
  連續 8 輪都不撞的機率約 **1.1%**（0.57⁸）。而本輪的偵測靈敏度**更高**（每輪 12–13 次持續
  取樣 vs 前置調查多數輪次只在啟動時判定一次），因此真實的 p 只會更高、這個機率只會更低。

## 這份證據的邊界（**不得被讀成比它更強**）

1. **不是隨機對照試驗。** 兩組執行在不同時間、不同機器負載下進行，未交錯、未盲化。
2. **`hidden` 的成因仍未查明。** 觀測到的是「處置之後不再出現」，不是「機制被解釋了」。
   虛擬螢幕上沒有視窗管理器、只有一個視窗 —— 「遮蔽」始終是推論（見 design D1 / Open Questions）。
3. **未拆分兩個旗標。** 哪一個承重不知道，也未驗證是否兩者皆需要。
4. **只涵蓋 `probe:openspec` 的一個段落。** 那是唯一能穩定重現該現象的載體；其餘探針的 dev 段
   在前置調查中未撞到（而那也可能只是取樣不足）。

**若日後再次觀測到 `hidden`**：本 change 的第 2 項（frame 診斷）會讓它說得出話，而 §4／§5／§6
不受影響 —— 它們與這個假說無關。
