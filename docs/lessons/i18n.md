# i18n 的教訓

> **觸發器**：動 `src/shared/i18n/`（含 `locale.ts`、`languages.ts`、任一份字典）、
> `scripts/dictionary-completeness.test.mjs` / `locale-source.test.mjs` / `probe-language.test.mjs`、
> 任何探針的啟動路徑、或任何會**格式化時間／數字／排序字串**的東西之前，把這份讀完。
>
> 這裡的每一條失效方式都是靜默的：畫面上不會有錯誤，只是排序怪怪的、時刻格式不對、
> 某一格突然變回英文，或者探針以「選不到元素」的樣子紅掉。

## 一、Electron 的 locale API —— 驅動者是 `LANGUAGE`，不是 `LANG`

實測（2026-09-18、Electron 43.1.0、Linux/xvfb）：

| `LANG` | `LANGUAGE` | `getLocale()` | `getSystemLocale()` | `getPreferredSystemLanguages()` |
|---|---|---|---|---|
| `zh_TW.UTF-8` | `zh_TW:zh` | `zh-TW` | `zh-TW` | `zh-TW,zh,zh` |
| `en_US.UTF-8` | `zh_TW:zh` | **`zh-TW`** | `en-US` | **`zh-TW,zh,zh`** |
| `zh_TW.UTF-8` | `en_US:en` | **`en-US`** | `zh-TW` | **`en-US,en,en`** |
| `zh_TW.UTF-8` | 未設 | `zh-TW` | `zh-TW` | `zh-TW,zh-TW,zh,zh` |
| 兩者皆未設 | | `en-US` | **`en-US@posix`** | **（空陣列）** |
| `zh_TW.UTF-8` | `zh_TW:zh` ＋ `--lang=en-US` | **`zh-TW`** | `zh-TW` | `zh-TW,zh,zh` |
| `zh_TW.UTF-8` | 未設 ＋ `--lang=en-US` | `en-US` | `zh-TW` | `zh-TW,zh-TW,zh,zh` |

四條結論：

1. **`LANGUAGE` 有值時它驅動一切**；`LANG` 只剩 `getSystemLocale()` 在看。
   **而這台開發機的兩者是不一致的**（`LANG=zh_TW.UTF-8`、`LANGUAGE=zh_TW:zh`）——
   一份只設 `LANG` 的驗收會得到與它宣稱相反的結果。
2. **`--lang` 不能用**：`LANGUAGE` 有值時它連 `getLocale()` 都蓋不掉。
3. **`getPreferredSystemLanguages()` 會回空陣列**（兩個變數都沒有時）。純函式的 `[]` 分支
   是一條量測到的輸入，不是假想的防禦。
4. **`getSystemLocale()` 會回傳 `en-US@posix`** —— 不是乾淨的 BCP-47 標籤，不適合當偵測來源。

> **第一版的實測是錯的，而錯法值得記**：那三行指令裡寫了 `LANGUAGE=""`，等於自己造了一個
> 乾淨環境卻不自知，於是得出「`LANG` 驅動全部三個」這個相反的結論，並據此寫了一整段 design。
> **量測環境本身也是被觀測的一部分。**

## 二、`aria-label` 是選擇器 —— 而它自己也會被翻譯

這是既有的結構性事實（見 CLAUDE.md），多語讓它多一層：

```js
// 切成中文之後，這個選擇器選不到任何東西
document.querySelector('aside[aria-label="Workspace"]')
```

**徵狀是 `null`，而 `null` 看起來像「介面沒變」，不像「選不到元素」** —— 第一次寫語言段落時
四條斷言一起回 `null`，第一直覺是「語言切換壞了」。處置：`scripts/lib/copy.mjs` 的
`copyIn(language, key)` / `labelIn(language, key)`，**驗收在哪一種語言下執行，選擇器就用
哪一種語言的字典**。

`copy()` / `label()` 兩個既有入口**維持只讀基準語言**，而探針的 profile 一律被種入基準語言
（`scripts/lib/probe-language.mjs`）—— 那是其餘每一段的前提，不是巧合。

- **種在共用的啟動路徑上，不是在每個建立 profile 的地方。** 一支探針只有一處
  `--user-data-dir=` 字面卻可能有數個 profile（`probe-workspace` 有四個）。
- **只在偏好檔不存在時才寫。** 於是「損毀韌性」與「沒有 `ui` 區塊的舊檔」那兩段不必列為
  例外 —— 它們寫在前，helper 就不動。
- **判定「有沒有傳 `--user-data-dir`」不能用 `includes()`** —— `probe-identity` 的斷言正是去
  **讀**子行程 argv 裡的那個旗標，字串比對會把它判成相反的事。

## 三、切換語言的入口只有一個，而 preload 的方法不是它

```js
window.workspace.settings.setLanguage('zh-TW')   // ← 只改了主行程
```

renderer 自己那份 i18n 是 `PreferencesProvider` 在 IPC resolve **之後**才套用的。以 preload
的方法驅動，畫面一個字都不會變 —— 而斷言看起來就像「排序沒有隨語言改變」。**驗收要走產品
自己的入口**（設定對話框的選單）。

順序是規格條款：**主行程先、renderer 後**。反過來時，套用失敗的那一刻畫面已是新語言而原生
對話框與通知還是舊語言，**而那個分岔不會產生任何錯誤**。

## 四、依賴陣列是「什麼時候該重算」的載體，而 locale 的依賴是隱形的

`useFileTree` 的列順序由跟著 UI 語言走的比較器決定，但 `state` 與 `rootPrefix` 在語言改變時
一個都沒有變 —— 樹會維持舊語言的排序**直到下一次目錄重新載入**。

而把 `language` 塞進依賴陣列會被 `exhaustive-deps` 判為「多餘」：比較器在函式內部去讀全域
語言，那條依賴**在語法上看不見**。一個 lint 說多餘的依賴，遲早會被刪掉。

處置：**讓格式化器收下語言**（`collator(language)`），依賴就成為一個真的值。
`src/shared/i18n/locale.ts` 的每一個取用者都有這個可選參數，理由不是彈性，是可見性。

同一族的第二個實例：`useFileTree` 的 `describeFailure()` 原本把**翻好的字串**存進
`state.errors`。存起來的字串不會自己更新 —— 失敗訊息會停在寫入當下的語言。處置是把失敗以
**結構**入 state，於呈現時才 `t()`（與「主行程拋出的錯誤帶不了 `code` 到 renderer」同形）。

> **`t()` 本身沒問題** —— 它於呼叫時解析當前語言。有問題的只有「把它的結果存起來」的地方。
> renderer 有五個模組直接 import module-level 的 `t`，其中只有一個存了值。
> **加新的 module-level `t` 消費者時要重問一次這個問題。**

## 五、字典完整性：三件事要比，而最不顯眼的是變數

`scripts/dictionary-completeness.test.mjs` 比對基底 key、CLDR 複數類別、插值變數集合、非空值。

- **複數類別不能用「key 集合完全相同」判定**。`Intl.PluralRules('en')` 是 `one`/`other`，
  `zh-TW` 只有 `other` —— 一道要求 key 集合相同的守衛，會對**每一份正確的翻譯**失敗，
  然後在第一次跑的時候就被改成 allowlist，然後就沒有守衛了。
- **變數要分兩層比，而分層的理由來自一個真實的反例**：天真的做法是拿基準語言該 key
  所有複數形式的**聯集**去要求每一個翻譯形式 —— 但英文的 `_one` 本來就可以不帶 `{{count}}`
  （`one thing` vs `{{count}} things`）。正確的是：**交集**（每個形式都有的變數）逐形式要求，
  **聯集**（整個 key）比對相等。這條是被自己的對照組抓出來的。
- **不做 allowlist。** 字典改為**先落地完整的 key 骨架**（值暫為原文）再逐批替換值，
  於是守衛從第一天起就是綠的 —— 而「暫時是紅的 `npm test`」幾天內就會變成沒有人在看的
  `npm test`。

## 六、完整性守衛看不見從來沒進過字典的字

它只保證「字典裡的每一條都翻了」。實際留在程式碼裡、從未進過字典的可見英文有：麵包屑的
`changes` / `specs` / `files`、`charts.tsx` 的 `WEEKDAYS`、`InsightsOverlay` 的四組分桶標籤，
以及 **`aria-label={\`${label} changes\`}` 這種合成的標籤**（`aria-label-source.test.mjs`
原本對以 `${` 開頭的值一律跳過，它整個逃掉了，而探針另一頭硬編著同一個後綴）。

**這一類沒有機械守衛**：「這個字串會不會被顯示」無法靜態判定，一道會誤報 `'utf8'`、`'\n'`
的守衛會立刻被加滿豁免。處置是把已知的補進字典，其餘由 dogfood 以中文介面認定。

> 順帶：`aria-label-source.test.mjs` **走行掃描**，在**註解**裡寫出該屬性的字面形式也會被
> 判違規。寫這份文件時就踩到了。

## 七、偏好檔「不存在」必須嚴格等同於「從未啟動過」

首次啟動的語言偵測以「`preferences.json` 不存在」為判準（**不是**「語言欄位未設定」——
後者會讓既有使用者在升級後自己換語言）。

而隔離路徑會把原檔**改名**保留，於是那個路徑就不存在了 —— 少了回寫，「壞過一次偏好檔」的
使用者會在下一次啟動時莫名其妙換了語言。`PreferencesStore.load()` 因此在隔離之後立刻回寫
一份預設檔。**D1 的整個論證都架在那個等式上。**

同族：偵測到的語言**要寫回去**。否則使用者在首次啟動被正確地帶到中文之後，只要他改一次
字型（偏好檔因此被寫出、而語言欄位仍是空的），下一次啟動就會退回英文。

## 八、既有的兩支 flaky 與這件事無關

`src/main/user-env.spawn.test.ts`（真 pty spawn）與 `scripts/cdp-transport.test.mjs`（真 port）
在**乾淨樹上**同樣會間歇性紅（實測 1/3～2/3）。多語的改動增加了平行負載，可能讓它們更容易
現形，但成因與 i18n 無關 —— 追 flaky 時不要從這裡開始找。
